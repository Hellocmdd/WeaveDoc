# WeaveDoc — Figma AI 页面定义（Full Page Definitions）

---

## PAGE 1: 工作台（Workspace）— 主页面

### 页面用途

WeaveDoc 的核心工作页面。用户在此页面中完成学术论文的写作、PDF 文献的阅读、参考文献的引用管理。所有其他页面（面板、对话框）均以此页面为锚点展开。用户 90% 以上的时间停留在此页面。

### 页面布局

```
┌──────────────────────────────────────────────────────────┐
│                    标题栏 (Title Bar)           _ □ ×     │  高度: 32px
├──────────────────────────────────────────────────────────┤
│ 菜单栏  File  Edit  View  AI  Literature  Export  Help    │  高度: 28px
├──────────────────────────────────────────────────────────┤
│ 工具条  [新] [开] [存] [导出] [AI] [撤销] [重做]            │  高度: 40px（图标按钮，文字为 tooltip）
├────────────────┬────────────────────────────┬─────────────┤
│                │                            │             │
│  PDF 阅读器     │    Markdown 编辑器          │ 上下文面板   │
│  (左侧分屏)     │    (右侧分屏)               │ (右侧边栏)   │
│                │                            │             │
│  宽度占比 35%   │    自动填充剩余宽度          │ 宽度: 280px │
│  最小宽度 300px│    最小宽度 400px           │ 可折叠      │
│                │                            │             │
│                │                            │             │
│                │                            │             │
├────────────────┴────────────────────────────┴─────────────┤
│ 状态栏  Ln 42, Col 18 │ 12,480 words │ Refs: 34 │ Sync On │ AI │ RAM │  高度: 24px
└──────────────────────────────────────────────────────────┘
```

- **总体窗口尺寸**：默认 1440×900px，最小支持 1024×700px
- **分屏比例**：上下文面板折叠时 PDF : Markdown = 35% : 65%；上下文面板展开时先预留 280px 面板宽度，再在剩余宽度内按 PDF 35% / MD 自动填充计算，并保证 PDF ≥300px、MD ≥400px
- **分屏可拖拽调整**：中间分隔线可左右拖动，PDF 宽度范围 25%–50%，双击分隔线重置为 35%
- **上下文面板**：窗口 ≥1440px 默认展开并保持完整三栏；1024–1439px 默认折叠（启动时面板宽度为 0）。用户通过工具条 Toggle AI Panel 按钮或快捷键 `Ctrl+Shift+A`/`Ctrl+Shift+L`/`Ctrl+Shift+T` 展开，展开时宽度固定 280px，挤压 Markdown 编辑器宽度
- **标题栏**：Windows/Linux 原生标题栏，包含窗口控制按钮

### 用户交互

| 交互动作       | 触发方式                                 | 反馈                                                       |

### 页面状态

| 状态                     | 场景                      | 表现                                                                                                                                |
| ------------------------ | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **首次启动空态**   | 新用户首次进入，无工作区  | PDF 阅读器显示空白占位（"拖入 PDF 文献以开始阅读"），MD 编辑器显示空白文档（"输入 Markdown 开始写作..."），状态栏显示"未打开工作区" |
| **正常编辑态**     | 已有工作区，正在写作      | 所有模块正常工作，状态栏实时更新                                                                                                    |
| **PDF 未加载态**   | 工作区中有 MD 但无 PDF    | PDF 阅读器显示占位提示："拖入 PDF 文献以开始阅读"，提供空态 [打开文件] 按钮；也支持拖拽 PDF 到阅读器区域                                                                    |
| **MD 未加载态**    | 工作区中有 PDF 但无 MD    | MD 编辑器显示占位提示："新建或打开 Markdown 文档以开始写作"，提供 [新建 Markdown] / [打开 Markdown] 操作入口 |
| **同步滚动断开态** | 用户关闭了双屏同步        | PDF 和 MD 各自独立滚动，状态栏显示 "Sync Off" 可点击项，点击可重新启用同步滚动                                                        |
| **大文档加载中**   | 打开 > 10000 字的 MD 文件 | MD 编辑器显示加载进度条，加载完成后进入正常编辑态                                                                                   |
| **内存告警态**     | 系统内存 > 80%            | 状态栏内存指示器变红，弹出 toast 建议释放 PDF 缓存 / 切换小模型 / 关闭其他应用；不静默卸载正在使用的模型（70–80% 时内存指示器变为橙色告警，不弹 toast）                           |
| **Zotero 断连态**  | .bib 文件路径不可达       | 状态栏引用计数旁显示 `StatusIcon(warning)`，tooltip 显示"Zotero 同步源不可用"                                                       |

### AI 功能区域

| 嵌入位置           | AI 功能       | 触发             | UI 形态                                        |
| ------------------ | ------------- | ---------------- | ---------------------------------------------- |
| 上下文面板 (Tab 1) | RAG 文献问答  | 点击 AI 面板 Tab | 嵌入在右侧面板内，详见 PAGE 2                  |
| PDF 阅读器上方     | 公式 OCR 提取 | 框选公式区域     | 浮动工具栏浮层，详见 PAGE 8                    |
| 状态栏右侧         | 模型状态监控  | 系统自动         | 微型状态指示器 — ModelStatusIndicator (compact)：颜色灯 + 模型名称；点击跳转 Settings → Model Management |
| MD 编辑器 / 文献面板内（未来） | 引文智能推荐 | 光标上下文 / 文献列表上下文 | 推荐可能相关的文献候选；不替代 `[@` 规则补全 |

> 当前 `[@` 引用自动补全基于 CitationIndex 规则匹配，不计入 AI 功能。

### 风格参考

类比工具组合：**VS Code 的分栏编辑体验 + Zotero 的 PDF 阅读体验 + Obsidian 的 Markdown 编辑体验**

- 整体 chrome 极简，工具条仅保留 7 个图标按钮
- PDF 阅读器和 MD 编辑器之间使用 VS Code 风格的拖拽分隔线
- 状态栏类似 VS Code 底部状态栏，灰底小字；文档状态左对齐，AI/内存等系统状态右对齐
- 上下文面板采用 VS Code 右侧面板的 Tab 切换模式
- 等宽字体用于 MD 编辑区，衬线字体用于 PDF 渲染
- 图标风格：简洁线条图标，16×16px，单色

## PAGE 2: AI 问答面板（Chat Panel）— 上下文面板

### 页面用途

用户在阅读 PDF 文献时，针对文献内容向本地 AI 助手提问。系统基于 RAG 机制检索相关段落，调用本地 LLM 生成带引用溯源的答案。全离线运行，无网络依赖。

### 页面布局

```
┌─────────────────────────────┐
│        面板头部               │  高度: 36px
│  [AI 问答] [文献] [快照]  [×] │  Tab 切换 + 折叠按钮
├─────────────────────────────┤
│      模型状态指示条           │  高度: 28px
│  🟢 Phi-4 7B · 3.2 t/s · 42%│  状态灯 + 模型名 + 性能（点击跳转 Settings）
├─────────────────────────────┤
│                             │
│       对话消息列表            │
│                    [Clear]   │  清空对话按钮
│  ┌─────────────────────┐    │
│  │ 用户: 本文提出的方法  │    │  用户消息气泡 (右对齐)
│  │ 是什么？            │    │  浅色背景
│  └─────────────────────┘    │
│                             │
│  ┌─────────────────────┐    │
│  │ AI: 本文提出了基于   │    │  AI 回答气泡 (左对齐)
│  │ 深度学习的...        │    │  含引用标注 [1][2]
│  │                     │    │
│  │ [1] p.3  [2] p.7   │    │  CitationChip 引用溯源链接 (可点击)
│  └─────────────────────┘    │
│                             │
├─────────────────────────────┤
│  基于已加载的 PDF 文献提问    │  追问提示
│       输入区                 │  高度: 88px
│  ┌─────────────────┐ [发送] │  输入框 + 发送按钮
│  │ 输入你的问题...   │ [⏹]  │  [⏹] = 停止生成（仅推理中可见）
│  └─────────────────┘        │
└─────────────────────────────┘
```

- **面板宽度**：固定 280px（继承上下文面板容器宽度）
- **面板高度**：继承工作区剩余高度（已扣除标题栏、菜单栏、工具条、状态栏）
- **垂直分区**：面板头部 (36px) → 模型状态条 (28px) → 对话列表 (flex: 1) → 输入区 (88px，含 60px 多行输入框本体)
- **对话列表**：纵向滚动，新消息自动滚动到底部

| **正常浏览态**   | 有快照，用户浏览中                      | 时间轴显示全部节点，选中某节点后预览区加载内容                                   |
| **预览加载中**   | 重建历史版本需要从基线 + diff 计算      | 预览区显示加载动画 / 骨架屏                                                      |
| **恢复确认态**   | 用户点击了恢复按钮                      | 模态确认对话框弹出，背景面板变暗                                                 |
| **恢复执行中**   | 用户确认恢复                            | 按钮显示"恢复中..."loading，编辑器内容替换，完成后时间轴刷新                     |
| **恢复完成态**   | 恢复成功                                | 预览区关闭，时间轴顶部出现新节点"(当前) 恢复到 16:30 版本"，编辑器显示恢复后内容。旧当前节点 "16:35 (当前)" 自动退化为普通历史节点 |
| **快照损坏**     | 某个快照文件因磁盘错误无法读取          | 该节点灰色不可点击，tooltip 显示"此快照已损坏"，其余节点正常                     |
| **预览内存不足** | 大文档重建时内存不足                    | 预览区显示错误提示："文档过大，无法预览。可尝试直接恢复。" 恢复按钮仍可用        |

### AI 功能区域

| 嵌入位置       | AI 功能              | 说明                                                                                          |
| -------------- | -------------------- | --------------------------------------------------------------------------------------------- |
| 时间轴节点     | 变更语义摘要（未来） | 当前 MVP 显示 "+N -M 行"；未来可由本地 LLM 自动生成变更语义描述，如"修改了第三章的方法论部分" |
| 恢复前风险评估 | 智能提示（未来）     | 恢复前由 LLM 对比当前版本与目标版本，提示可能丢失的关键内容                                   |

### 风格参考

**类似 GitLens 的提交时间轴 + macOS Time Machine 的恢复体验**

- 时间轴竖线连接所有节点，类似 Git 提交历史图
- 当前版本用实心圆点明确标记，与历史节点形成视觉区分
- 预览区复用 MarkdownEditor 的只读预览变体，保持字体、滚动与选中文本行为一致
- diff 视图类似 VS Code 的 source control diff 视图
- 恢复操作是破坏性的，必须通过模态确认对话框保护

## PAGE 8: 公式提取浮动工具栏（OCR Floating Toolbar）— 上下文浮层
