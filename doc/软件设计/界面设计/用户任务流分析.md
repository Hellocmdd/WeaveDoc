# WeaveDoc 用户任务流分析（Task Flow Analysis）

---

# 用户角色

| 角色 | 描述 | 核心诉求 |
|------|------|---------|
| **学术写作者（Primary）** | 高校本科生、研究生、初级科研人员；熟悉 Markdown，认为 LaTeX 门槛过高；已有 Zotero + Markdown 工具使用习惯 | "让我专注内容，排版的事交给系统" |
| **文献阅读者** | 同一人群在文献调研阶段的行为角色；需要从大量 PDF 中提取关键信息 | "帮我在一堆论文里快速找到答案" |

> 两种角色为同一用户在不同工作阶段的表现，非独立用户类型。

---

# 用户目标

| 编号 | 用户目标 | 对应核心 JTBD（Jobs To Be Done） | 优先级 |
|------|---------|----------------------------------|--------|
| G1 | 将 Markdown 手稿导出为符合学校/期刊规范的 Word/PDF | "当我写完论文时，帮我生成符合规范格式的提交稿" | Must Have |
| G2 | 在写作时同步阅读参考 PDF，并在文中留下精准定位锚点 | "当我引用 PDF 中的某段内容时，帮我标记原文位置" | Should Have |
| G3 | 针对已加载的 PDF 文献提问，获取带原文溯源的答案 | "当我读不懂论文时，帮我找到答案并告诉我在哪一页" | Must Have |
| G4 | 从 PDF 中提取复杂数学公式转为 LaTeX 代码 | "当我在 PDF 里看到一个公式想复用时，帮我转成可编辑代码" | Must Have |
| G5 | 自动管理参考文献的编号与排序，确保引用一致性 | "当我增删引用时，自动帮我重新编号，别让审稿人发现序号乱了" | Must Have |
| G6 | 回滚到文稿的某个历史版本 | "当我改坏了想回到之前某个状态时，帮我找回来" | Could Have |

# 核心任务流

## 任务流 1：从头写一篇学术论文并导出为 Word

**用户目标**：完成一篇符合学校学位论文格式规范的 Word 文档

**前置条件**：
- 系统已安装并首次启动
- 用户已准备目标格式的 AFD 模板文件（如 `whu-thesis.json`）
- 用户已通过 Zotero Better BibTeX 导出 `.bib` 文献库，并置于工作区目录

**触发条件**：用户新建工作区，开始撰写 Markdown 文档

### 步骤

1. **创建工作区**
   - 用户在系统中新建一个工作区目录
   - 系统在本地文件系统中创建工作区文件夹，初始化 SQLite 索引

2. **确认模板库可用**
   - 系统扫描已注册的 AFD 模板，确保至少存在一个可导出的模板
   - 目标排版模板在导出对话框中选择，避免写作阶段提前绑定格式

3. **编写正文（循环进行）**
   - 用户在 Markdown 编辑器中撰写论文正文、公式、表格
   - 系统实时更新语法高亮、引用标记内联预览和锚点渲染，每次击键延迟 < 30ms

4. **插入文献引用**
   - 用户在文中插入引用标记 `[@author2023]`
   - 系统从已解析的 BibTeX 库中匹配条目，建立引用映射关系
   - 系统即时建立引用映射并显示预览；正式正文编号和文末参考文献列表在导出阶段统一重排

5. **发起导出**
   - 用户打开导出对话框，选择目标模板，确认输出格式（Word/PDF）和完整输出文件路径（含文件名和扩展名）
   - 系统校验输入参数（模板 ID 非空、路径合法）

6. **等待系统处理**
   - 系统执行以下管线：解析 AFD 模板 → Markdown 生成 IR 中间表示 → 引文重排 → Pandoc 转换 → 输出文件
   - 用户看到进度条指示当前阶段（"正在解析模板..." → "正在生成 IR..." → "正在重排引文..." → "正在执行 Pandoc 转换..."）

7. **获得成品文档**
   - 系统在指定路径生成 `.docx` 或 `.pdf` 文件
   - 系统记录本次导出操作至审计日志

### 系统反馈
- 每个处理阶段有明确的进度文案
- 导出成功：提示"导出成功"并显示文件路径
- 引用匹配结果在编辑器中即时可见；正式编号重排在导出阶段完成，避免编辑过程频繁闪烁

### 异常情况
| 异常 | 系统行为 |
|------|---------|
| AFD 模板 JSON Schema 校验失败 | 拒绝导出，返回具体校验错误字段列表 |
| BibTeX 中存在未匹配的引用标记 | 导出前警告用户，列出未解析的引用键 |
| Pandoc 子进程崩溃 | 捕获退出码，向用户展示错误详情，不丢失编辑器中内容 |
| 目标路径无写入权限 | 导出前校验，提示用户更换路径 |

### 结束状态
- 用户获得符合规范的 Word/PDF 文件
- 编辑器中保留完整的 Markdown 源文件
- 审计日志中记录本次导出操作

## 任务流 2：双屏阅读 PDF 文献并在文中建立深层链接锚点

**用户目标**：在阅读参考文献 PDF 的同时，将 PDF 中的特定段落/图表与 Markdown 手稿中的引用位置绑定，实现"从引文一键跳转到原文出处"

**前置条件**：
- 工作区中已加载至少一个 PDF 文件
- Markdown 编辑器和 PDF 阅读器处于分屏模式
- 系统已解析 BibTeX 文献库，PDF 文件与文献条目已建立匹配

**触发条件**：用户在分屏视图中点击 PDF 中的某个段落或图表区域

### 步骤

1. **打开分屏视图**
   - 用户在系统中打开一个 Markdown 文档和一个关联 PDF
   - 系统渲染左右分屏布局：左侧 PDF 阅读器，右侧 Markdown 编辑器

2. **同步阅读（可选）**
   - 用户滚动 Markdown 编辑器
   - 系统根据引用标记位置自动滚动 PDF 到对应页面（双向同步联动）

3. **在 PDF 中定位目标段落**
   - 用户在 PDF 中浏览，找到需要引用的段落或图表
   - 系统提供 PDF 缩放、翻页等基础阅读操作

4. **生成锚点**
   - 用户点击 PDF 中的目标区域（段落或图表）
   - 系统生成深层链接锚点（包含 PDF 页码、段落位置信息）

5. **锚点插入 Markdown**
   - 系统自动在右侧 Markdown 编辑器当前光标位置插入锚点链接（如 `[ref:page3-para2]`）
   - 用户可在 Markdown 中看到锚点标记

6. **反向跳转（验证）**
   - 用户在 Markdown 中点击锚点链接
   - 系统自动将 PDF 滚动到对应段落位置

### 系统反馈
- 锚点插入时，Markdown 编辑器中有光标闪烁定位
- PDF 侧高亮标记已锚定的区域
- 双向跳转延迟 < 30ms（NFR-01）

### 异常情况
| 异常 | 系统行为 |
|------|---------|
| PDF 图层解析失败（扫描版 PDF） | 提示用户该 PDF 为扫描件，无法生成文本级锚点，降级为页码级锚点 |
| 光标不在 Markdown 编辑器中 | 锚点暂存，待用户点击编辑器后再插入 |

### 结束状态
- Markdown 文档中多处嵌入了 PDF 深层链接锚点
- PDF 中已锚定的区域被标记
- 用户可以随时从 Markdown 锚点跳转回 PDF 原文位置

## 任务流 3：离线 AI 文献问答（RAG）

**用户目标**：针对已加载的 PDF 文献内容提出问题，获得基于原文上下文的准确回答，并明确知道答案出自文献的哪一部分

**前置条件**：
- 系统已配置本地 LLM 模型（GGUF 格式）和 Embedding 模型；若尚未加载，可通过 Settings → Model Management 显式加载；若用户在 Settings → Model Management 中开启"AI 面板自动加载"，打开 AI 面板后进入加载状态
- 至少一个 PDF 文件已被导入工作区；向量化索引可已完成，也可在 AI 面板打开后继续构建
- 设备处于离线状态（断网 / 飞行模式）

**触发条件**：用户打开 AI 问答面板，输入问题

### 步骤

1. **打开问答面板**
   - 用户点击 AI 助手入口
   - 若已配置并在 Settings → Model Management 开启"AI 面板自动加载"，系统显示"正在加载模型..."进度指示，依次加载 LLM 模型和 Embedding 模型；否则显示"模型未加载"，用户点击状态条跳转到 Settings → Model Management 后手动加载
   - PDF 导入时已自动触发向量化；若打开 AI 面板时仍有未索引或未完成索引的 PDF，系统继续对文本进行分块（512 tokens/块，重叠 50 tokens）并向量化存入 SQLite

2. **等待就绪**
   - 系统完成模型加载和向量索引构建后，隐藏进度条
   - 显示"AI 助手已就绪"（冷启动总时间 < 5s，满足 NFR-02）

3. **输入问题**
   - 用户在问答面板中输入自然语言问题，如"本文提出的方法是什么？"
   - 系统接收问题文本

4. **检索相关段落**
   - 系统将用户问题向量化，在本地向量库中计算余弦相似度
   - 返回 Top-5 最相关的文本片段（含 PDF 页码和段落位置）

5. **组装 Prompt 并推理**
   - 系统将检索结果组装为 System Prompt：
     > "你是一个学术助手。基于以下文献内容回答问题：{检索结果} --- 问题：{用户问题}"
   - 系统调用本地 LLamaSharp 模型进行推理

6. **流式接收回答**
   - 系统以流式方式逐 Token 展示 AI 回答（首字响应时间 < 2s，满足 NFR-02）
   - 回答末尾附带引用溯源链接，点击可跳转到 PDF 对应页面

7. **追问（可选）**
   - 用户基于回答继续提问
   - 系统将对话历史纳入上下文，重复步骤 3-6

### 系统反馈
- 模型加载阶段：进度条 + "正在加载模型..."
- 向量化阶段：进度条 + "正在索引文档... (X/Y 页)"
- 推理阶段：流式文字输出，逐 Token 打印
- 回答完成：渲染引用标注，高亮原文出处

### 异常情况
| 异常 | 系统行为 |
|------|---------|
| LLM 模型文件缺失或损坏 | 提示用户下载/更换模型文件，引导至模型配置页 |
| 推理速度低于 2 tokens/s | 提示用户可切换更小的模型（如 3B 替代 7B），启用降级策略 |
| PDF 文本提取失败（扫描件/加密） | 提示该 PDF 无法向量化，跳过该文档，继续处理其他文献 |
| 内存占用达到 warning / critical 阈值 | 默认阈值下 70–80% 触发橙色预警与 tooltip 建议，>80% 触发红色告警和 toast；若用户在 Settings 修改 critical 阈值，则 warning 区间随阈值前移。系统提示用户关闭其他应用、释放缓存或切换小模型；不静默卸载正在使用的模型 |
| 对话上下文超出模型窗口 | 自动截断早期对话，提示用户"上下文已滚动" |

### 结束状态
- 聊天面板中保留完整对话记录（带引用溯源）
- 用户对文献内容有了基于原文的理解
- 所有处理完全在本地完成，零网络请求

## 任务流 4：从 PDF 提取数学公式为 LaTeX 代码

**用户目标**：当在 PDF 中看到一个复杂数学公式想在自己的论文中复用时，一键提取并转换为可编辑的 LaTeX 代码

**前置条件**：
- 系统已配置本地 OCR 视觉模型；若尚未加载，可由本次框选公式这一显式操作触发加载
- PDF 文件已在阅读器中打开
- 设备处于离线状态

**触发条件**：用户在 PDF 阅读器中框选一个公式区域

### 步骤

1. **框选公式区域**
   - 用户在 PDF 阅读器中使用鼠标拖拽框选一个数学公式区域
   - 系统显示选区边框

2. **自动触发提取**
   - 用户松开鼠标后，公式提取浮动工具栏自动弹出
   - 系统截取选区内的图像并开始识别

3. **OCR 识别**
   - 系统将截取的公式图像传入本地 OCR 视觉模型
   - 系统显示"正在识别公式..."加载状态

4. **获得 LaTeX 代码**
   - 系统输出识别结果：标准 LaTeX 代码字符串
   - 用户点击"复制 LaTeX"后，系统将 LaTeX 代码复制到系统剪贴板

5. **粘贴使用（用户侧）**
   - 用户切换到 Markdown 编辑器，粘贴 LaTeX 代码
   - LaTeX 公式在 Markdown 中以 `$...$` 或 `$$...$$` 形式渲染

### 系统反馈
- 框选时有视觉高亮边框
- OCR 处理中有进度指示
- 识别完成：展示 LaTeX 代码；用户点击复制后显示"已复制到剪贴板"提示

### 异常情况
| 异常 | 系统行为 |
|------|---------|
| 框选区域不包含公式（误选正文） | OCR 返回空或乱码，系统提示"未识别到公式，请重新框选" |
| 公式复杂度过高超出现有模型能力 | 返回部分识别结果，标注"部分识别" |
| OCR 模型未加载 | 由框选公式这一显式操作触发加载，在浮层内显示等待提示和取消入口 |

### 结束状态
- 用户剪贴板中已有 LaTeX 公式代码
- 用户可将其粘贴到 Markdown 编辑器中

## 任务流 5：管理参考文献（BibTeX 同步与引文自动重排）

**用户目标**：在写作过程中随时增删文献引用，系统自动维护引用编号的一致性和文末参考文献列表的正确性

**前置条件**：
- Zotero 已在后台运行并启用 Better BibTeX 插件
- Better BibTeX 已配置自动导出 `.bib` 文件至工作区目录
- 系统已获得读取 `.bib` 文件和写入本地索引的权限

**触发条件**：用户在 Markdown 中插入、移动或删除文献引用标记 `[@key]`

### 步骤

1. **首次配置 Zotero 同步**
   - 用户在系统设置中指定 Zotero Better BibTeX 导出的 `.bib` 文件路径
   - 系统解析 `.bib` 文件，构建 BibEntry 实体集合，存入 SQLite

2. **后台持续同步**
   - 系统监控 `.bib` 文件变更
   - 当用户在 Zotero 中新增/修改文献条目时，Better BibTeX 自动更新 `.bib` 文件
   - 系统检测到文件变更后，增量同步至本地索引

3. **在文中使用引用**
   - 用户在 Markdown 中写入或粘贴引用键，如 `[@he2024llm]`
   - 系统即时检测引用标记，查询 CitationIndex 匹配文献元数据
   - 系统显示引用预览（作者、年份）作为内联提示

4. **引文自动重排（触发时机）**
   - 用户在文中插入新引用、删除引用、或调整引用位置时
   - 系统记录引用顺序变化并维护候选排序
   - 正式正文编号和文末参考文献列表序号仅在导出阶段写入，避免编辑过程频繁闪烁

5. **导出前的最终校验**
   - 用户点击导出时，系统检查是否存在引用键无法匹配的 `[?]` 标记
   - 如有普通未解析引用，在导出前对话框展示警告列表，用户可选择保留原始标记继续导出
   - 如发现正文引用编号与文末条目无法对应等结构性不一致，系统阻断导出并要求返回修改

### 系统反馈
- 引用标记旁即时显示文献预览 tooltip
- 引用编号变更时，仅在导出阶段一次性更新（避免编辑过程中的频繁闪烁）
- 未匹配引用标记以 `warning` 样式（橙色下划线）标注

### 异常情况
| 异常 | 系统行为 |
|------|---------|
| `.bib` 文件被用户手动删除 | 系统提示同步源丢失，保留已索引数据，暂停自动同步 |
| Zotero v6/v7 导出格式差异 | 适配器自动检测版本，兼容两种格式 |
| BibTeX 条目缺少必填字段（如 author、year） | 标记为不完整条目，在引用预览中显示警告 |
| 引用键与 BibTeX 条目无法匹配 | 在编辑器中以红色标记；导出前展示清单，用户可返回修改或选择保留原始标记继续导出 |
| 正文引用与文末参考文献结构不一致 | 阻断导出，展示不一致原因和第一个问题位置 |

### 结束状态
- 导出后正文所有引用编号一致且连续
- 导出后文末参考文献列表与正文一一对应
- 引用关系可溯源至 Zotero 中的原始条目

## 任务流 6：恢复文稿历史版本（快照回滚）

**用户目标**：当写作过程中发现当前版本不如某个历史版本时，快速找回并恢复

**前置条件**：
- 系统后台快照服务已启用（默认每 5 分钟自动触发）
- 至少存在一个历史快照

**触发条件**：用户打开快照时间轴面板

### 步骤

1. **打开快照时间轴**
   - 用户在系统中打开"版本历史"面板
   - 系统从 SnapshotStore 加载当前文档的所有快照记录

2. **浏览历史版本**
   - 用户沿时间轴浏览各快照节点（每个节点显示时间戳和变更摘要）
   - 系统展示快照列表 / 可视化时间轴

3. **预览某个快照**
   - 用户点击某个快照节点
   - 系统在临时预览区渲染该历史版本的 Markdown 内容（只读）

4. **选择恢复**
   - 用户确认要恢复到选中的快照版本
   - 系统弹出确认对话框："当前未保存的更改将被覆盖。系统将在恢复前自动保存一个保护性快照。确定恢复？"

5. **执行恢复**
   - 用户确认后，系统从基线和增量 diff 重建目标版本
   - 系统先生成当前编辑器内容的保护性快照，再用重建内容覆盖当前编辑器缓冲区

6. **继续编辑**
   - 编辑器显示恢复后的内容
   - 后台快照服务继续运行，新的编辑操作将生成后续快照

### 系统反馈
- 时间轴面板显示快照时间、变更量摘要
- 预览模式下只读展示历史内容
- 恢复操作有二次确认对话框
- 恢复完成后编辑器内容即时更新

### 异常情况
| 异常 | 系统行为 |
|------|---------|
| 快照文件损坏（磁盘 I/O 错误） | 跳过损坏快照节点，在时间轴上标记为"不可用" |
| 恢复过程中系统崩溃 | 恢复操作在临时缓冲区执行，原编辑器内容不受影响，重启后恢复原状态 |
| 无可用快照 | 提示"暂无历史版本"，建议用户确认快照服务是否启用 |

### 结束状态
- 编辑器内容被重置为历史版本
- 被覆盖前的当前状态已立即保存为保护性快照，后续编辑仍按 5 分钟策略生成新快照
- 旧快照不被删除，用户仍可回滚到其他版本

## 任务流 7：首次安装与工作环境配置

**用户目标**：在首次使用 WeaveDoc 时完成必要的环境配置，使系统进入可写作状态

**前置条件**：
- 操作系统为 Windows 10/11 (64位) 或 Ubuntu 22.04+
- CPU 支持 AVX2 指令集
- 内存 >= 16GB（推荐）；低于 8GB 时首次配置向导给出警告，允许继续但不保证 AI 推理性能
- .NET 10.0 Runtime 已安装
- Pandoc 3.x 已安装并在 PATH 中

**触发条件**：用户首次启动 WeaveDoc.exe

### 步骤

1. **启动系统**
   - 用户双击 WeaveDoc.exe
   - 系统初始化 .NET 运行时，加载 Avalonia UI，冷启动 < 5s

2. **环境检测**
   - 系统自动检测 Pandoc 是否在 PATH 中，校验版本兼容性
   - 如未检测到 Pandoc，提示用户安装并给出下载链接

3. **配置 AI 模型**
   - 用户显式选择下载或本地导入 GGUF 格式的模型（LLM + Embedding + OCR）
   - 系统检测可用内存，推荐合适规模的模型（7B / 3B / 1.5B）

4. **关联 Zotero（可选）**
   - 用户指定 Zotero Better BibTeX 导出的 `.bib` 文件路径
   - 系统首次解析并索引所有文献条目

5. **导入 AFD 模板**
   - 系统扫描内置模板目录，自动注册已安装的 AFD 模板
   - 用户可额外导入自定义 JSON 模板文件

6. **进入主工作区**
   - 配置完成，用户可新建或打开工作区开始写作

### 系统反馈
- 环境检测结果以清单形式展示，每项使用 `success` / `warning` / `error` 状态（如 Pandoc 可用、模型未配置、磁盘空间充足）
- 模型下载有进度条和预计剩余时间
- 配置项提供"稍后设置"跳过选项

### 异常情况
| 异常 | 系统行为 |
|------|---------|
| 系统不满足最低硬件要求 | 启动时告警，列出不达标项，允许继续但不保证性能 |
| Pandoc 版本不兼容 | 提示最低版本要求，给出升级引导 |
| 磁盘空间不足以下载模型 | 提示清理空间或更换模型存储路径 |

### 结束状态
- 系统进入主工作区界面
- 基础编辑可用；导出能力取决于是否存在至少一个已注册且通过 Schema 校验的 AFD 模板。AI 问答、文献同步、OCR 等功能取决于用户是否完成对应模型和 Zotero 配置
- 配置可随时在设置中修改

# 高风险体验点

| 风险点 | 涉及任务流 | 体验风险描述 | 建议缓解方向 |
|--------|-----------|-------------|-------------|
| **模型冷启动等待焦虑** | TF3, TF4, TF7 | 用户首次打开 AI 问答或公式提取时，需要等待 LLM/OCR 模型加载，若进度指示不清晰，用户可能认为系统卡死 | 采用分阶段进度文案（"正在加载模型权重... 40%"），避免无差别 spinner；允许用户在模型加载期间先编辑文档 |
| **PDF 扫描版降级体验** | TF2, TF3, TF4 | 用户导入扫描版 PDF 后，文本提取/向量化/锚点生成均可能失败或精度大幅下降，但用户未必理解"扫描件"与"文字版 PDF"的区别 | 在导入 PDF 时主动检测并标注 PDF 类型（文字版/扫描版），对扫描版提前收敛预期，提供降级后的可用功能说明 |
| **引文序号错乱的信任危机** | TF1, TF5 | 如果引文重排逻辑存在边界 bug（如同一个 key 出现多次、增删交叉引用），导出的 Word 中引用序号与文末列表不一致，将直接导致学术不规范的严重后果 | 导出前增加引用一致性校验步骤。结构性不一致（正文编号与文末条目无法对应）阻断导出；单个未匹配引用可由用户选择保留原始标记继续导出 |
| **Pandoc 转换失败时内容丢失恐惧** | TF1 | 用户点击导出后如果 Pandoc 崩溃返回错误，用户最担心的是"我的原稿是不是丢了" | 导出管线全程操作临时副本，编辑器中原始内容不受任何影响；错误提示中明确声明"原稿安全" |
| **内存压力下的 AI 功能降级** | TF3, TF4 | 在 16GB 设备上同时运行 PDF 渲染 + LLM 推理 + 向量检索可能触发内存告警，若模型突然卸载，用户正在进行的 AI 问答中断 | 在内存接近阈值前主动预警，提供"释放 PDF 缓存"/"切换小模型"等选项，而非静默卸载 |
| **快照恢复覆盖当前内容** | TF6 | 用户恢复历史版本后，当前编辑器内容会被覆盖；若提示不清晰，用户会担心当前改动无法找回或误触恢复 | 恢复前强制预览 + 二次确认弹窗；恢复前先生成保护性快照，保存被覆盖的"当前版本" |

# 可 AI 增强节点

以下节点在当前 MVP 设计中已由本地 AI 覆盖或可以进一步扩展：

| 节点 | 涉及任务流 | 当前 AI 角色 | 增强潜力 |
|------|-----------|-------------|---------|
| **RAG 文献问答** | TF3 | 本地 LLM + 向量检索，提供带溯源的文献问答 | 当前已实现。后续可增加：多文档跨文献对比问答、假设性提问（"如果我把这个方法换成 X 会怎样"） |
| **公式 OCR → LaTeX** | TF4 | 本地视觉模型识别公式区域 | 当前已实现。后续可增加：手写公式识别、整页公式批量提取 |
| **引文智能推荐** | TF1, TF5 | 无（当前为规则引擎） | 可引入：基于当前光标上下文（段落语义）推荐关联文献引用、检查"引用缺失"（某些论断缺少引用支持） |
| **写作风格一致性检查** | TF1 | 无 | 可引入：检测术语使用不一致（如"机器学习"/"Machine Learning"混用）、摘要字数超限提示 |
| **导出前格式校验增强** | TF1 | 无（当前为 Schema 校验 + 引用校验） | 可引入：基于目标模板规范的智能检查（如"硕士论文要求页眉从第 X 页开始，当前设置从第 Y 页开始"） |
| **快照节点语义标注** | TF6 | 无 | 可引入：自动为快照生成语义摘要（如"修改了第三章的方法论部分"），替代当前的时间戳标注 |
| **Zotero 文献去重与合并** | TF5 | 无 | 可引入：基于标题/DOI 相似度检测重复导入的文献条目 |
