# 访谈+观察目录：需求证据说明

## 1. 文档目的

本目录用于沉淀访谈纪要与需求提炼结果，服务于以下目标：

- 还原真实用户工作流与痛点场景。
- 为功能定义与优先级排序提供可追溯证据。
- 形成从“原始访谈”到“需求清单”的闭环链路。

## 2. 文件清单

- `访谈-任逸青.md`：单人访谈纪要（学术写作与本地工具体验）。
- `访谈-张启涵.md`：多人访谈合并纪要（提纲式问答整理）。
- `访谈-谭博友.md`：单人访谈纪要（科研工具使用交流）。
- `访谈-张超.md`：双对象访谈纪要（本科/博士对照），已按统一模板重排。
- `访谈+观察需求清单.md`：基于访谈与观察联合提炼的需求清单与优先级。
- `原始素材/`：原始文本、草稿或来源材料归档。
- `README.md`：本目录使用说明与维护规范（本文件）。

## 3. 数据来源与范围

- 来源类型：项目组访谈记录（人工问答与会后整理）。
- 内容范围：
	- 文献阅读与笔记习惯
	- AI 辅助写作与提问场景
	- Word/LaTeX/Markdown 排版与导出痛点
	- 文件管理、界面偏好、部署偏好
	- 真实写作全流程观察（任务分流、资料处理、成稿推进、排版交付）
- 数据形态：以自然语言纪要为主，属于半结构化文本。

## 4. 推荐信息结构（提炼时使用）

说明：访谈文件并非固定 JSON/CSV 结构。为保证可比性，建议在提炼需求时遵循下列信息结构。

| 维度 | 示例内容 |
|---|---|
| 受访对象 | 学生/研究者/年级/场景背景 |
| 任务类型 | 课程论文、实验报告、毕业论文、科研论文 |
| 工具链 | Word、Overleaf、Obsidian、AI 工具等 |
| 痛点 | 格式迁移、排版成本、多窗口切换、网络限制 |
| 需求 | 文献阅读、标注、AI 总结、导出一致性、文件管理 |
| 约束 | 设备性能、是否接受本地部署、隐私敏感度 |
| 证据 | 访谈原句或纪要段落 |

## 5. 最小使用流程

### 5.1 从访谈到需求清单

1. 通读 `访谈-任逸青.md`、`访谈-张启涵.md`、`访谈-谭博友.md`、`访谈-张超.md`，标记高频痛点与高价值场景。
2. 同步提炼每份纪要中的“观察受访对象的真实写作全流程”环节，形成可比较步骤链路。
3. 按“阅读-笔记-AI-排版-导出-管理-部署”维度聚类。
4. 依据证据强度与出现频次更新 `访谈+观察需求清单.md` 的优先级（P0/P1/P2）。

### 5.2 证据追溯原则

- 每条高优先级需求至少对应 1 条可定位的访谈证据，并尽量映射到具体流程环节。
- 若不同受访者观点冲突，保留差异并注明适用场景，不做强行合并。
- 需求描述优先使用行为化语言（做什么、在哪一步、被什么阻塞）。

## 6. 质量与局限

- 样本规模有限：访谈人数较少，结论应与其他数据源交叉验证。
- 表达偏差：受访者叙述可能受当下任务与记忆影响。
- 记录偏差：纪要属于整理文本，非逐字转写，可能损失细粒度语气信息。

建议：

- 对关键需求进行二次访谈或快速回访确认。
- 与“智能化辅助文档”中的外部社区反馈做对照，避免单源偏差。

## 7. 合规与使用边界

- 访谈内容仅用于课程项目研究与需求分析。
- 对外展示时避免披露可识别个人身份信息。
- 未经允许，不将原始访谈全文用于公开传播。

## 8. 与项目需求文档的关系

本目录提供的是“深度场景证据”，适合回答以下问题：

- 用户在实际写作链路中最卡的步骤是什么？
- 哪些能力必须一体化，哪些能力可作为增强项？
- P0 需求是否真实、稳定、可验证？

建议将本目录结论与 `PDF_查看器_需求_v2.0.md`、`智能化辅助文档` 的统计证据联合使用，形成“访谈+观察深描 + 社区广度”双证据框架。
