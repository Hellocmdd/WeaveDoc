# 访谈+观察需求清单

## 一、需求来源
本清单基于四份访谈纪要与对应观察环节联合提炼，覆盖以下来源文件：

- `访谈-任逸青.md`
- `访谈-张启涵.md`
- `访谈-谭博友.md`
- `访谈-张超.md`

聚焦科研写作、文献阅读、AI 辅助、排版导出、界面形态与真实写作全流程中的关键阻塞点。

## 二、核心需求

### 1. 文献阅读更顺手
- 支持直接打开 PDF 文献进行阅读。
- 支持先看目录、再跳读相关章节的阅读方式。
- 支持对文献进行快速翻译和摘要总结。
- 支持对重点内容进行定位，便于后续回看。
- 支持多文献、多页面同时打开。

### 2. 笔记与标注更方便
- 支持高亮、批注和摘录。
- 支持边看文献边做笔记，减少在多个窗口之间切换的成本。
- 支持把 PDF 里的关键内容快速转移到笔记中。
- 支持和聊天记录、分析记录联动回看。

### 3. AI 辅助要贴近真实写作流程
- 支持直接对文献提问，不必先上传到外部 AI 平台。
- 支持 AI 先做总结，再辅助用户进入细读阶段。
- 支持 AI 帮助生成初稿、改写、润色和中英互译。
- 支持 AI 处理手写公式转 LaTeX、实验报告整理、代码生成等任务。
- 支持 AI 对上下文进行理解，而不只是做简单摘要。
- 支持 AI 作为“对话者”与用户讨论和辩论内容。

### 4. 排版与导出要低成本
- 支持像写 Markdown 一样简单的编辑体验。
- 支持最终导出为学校或期刊要求的 Word、PDF 或 LaTeX 格式。
- 尽量减少 Markdown、Word、LaTeX 之间的反复转换。
- 需要降低公式排版、页眉页脚、目录、对齐等格式处理成本。
- 支持公式截图、公式识别或公式导出能力。

### 5. 文件管理要清晰
- 支持像文件管理器一样浏览和打开文件夹内文献。
- 支持减少手动拖拽文件的操作。
- 支持直接管理文献、笔记和导出文件。

### 6. 界面要简洁但能力完整
- 整体界面希望简洁，不要过于复杂。
- 不能像传统 IDE 一样堆叠过多按钮，避免用户望而却步。
- 也不能过于弱化功能，最好能兼顾完整性和可用性。

### 7. 部署方式要灵活
- 优先支持云端 API key 方案。
- 对本地部署没有强烈偏好，除非它足够轻量、易维护。
- 若提供离线能力，最好作为加分项而不是强制项。

## 三、主要痛点
- 不同编辑工具之间格式转换容易乱码，迁移成本高。
- Word 排版复杂内容耗时较长。
- 网络环境切换麻烦，影响文献检索和工具使用。
- 屏幕空间不足时，多工具并行操作不方便。
- AI 生成内容风格不统一，影响一致性。

## 四、全流程观察汇总

基于四份“访谈+观察”纪要，受访对象真实写作流程可归纳为 6 个连续环节：

1. 任务分流：先判断任务类型（课程论文/实验报告/科研论文），再决定工具链（Word/Overleaf/Markdown/AI）。
2. 资料获取：检索并下载文献，通常先做目录级筛选，不直接进入通读。
3. 快速理解：先翻译/摘要/问答，再回到原文细读关键段落。
4. 笔记沉淀：边读边记，常见是双窗口（PDF + 笔记工具）或聊天记录回看。
5. 成稿与改写：AI 参与初稿组织、改写润色，人工负责逻辑和最终表达一致性。
6. 排版与交付：后期集中处理模板、公式、目录、导出格式；跨工具迁移是主要风险点。

### 流程环节到功能优先级映射（P0/P1）

| 流程环节 | 关键阻塞点 | 对应能力 | 优先级 |
|---|---|---|---|
| 任务分流 | 工具入口分散、切换成本高 | 一体化工作台、统一入口 | P0 |
| 资料获取 | 多文献并行效率低 | 多文档打开、文件夹直读 | P1 |
| 快速理解 | 先理解再细读缺少闭环 | 文献问答、摘要、翻译联动 | P0 |
| 笔记沉淀 | 读写窗口割裂、证据难回溯 | 高亮批注、摘录回链、笔记联动 | P0 |
| 成稿与改写 | AI 输出风格不稳 | 上下文感知改写、风格一致性控制 | P1 |
| 排版与交付 | Word/LaTeX/Markdown 迁移损耗大 | 低摩擦导出、模板一致性、公式处理 | P0 |

## 五、优先级建议
- P0：文献阅读、笔记联动、高亮批注、AI 总结、减少格式转换。
- P1：公式处理、导出 Word/PDF/LaTeX、文件管理器、批量打开文献、上下文一致性检查。
- P2：离线部署增强、公式推导、对话式 AI、个性化写作支持。

说明：高敏场景存在“本地化 AI”刚性诉求，但从全样本看不属于通用必选项，建议作为可选增强能力分阶段推进。

## 六、结论
- 这个工具的核心价值应是把“看文献、做笔记、问 AI、整理成文”串成一个低摩擦流程。
- 用户最在意的不是功能堆叠，而是能否真正减少切换成本和排版成本。
