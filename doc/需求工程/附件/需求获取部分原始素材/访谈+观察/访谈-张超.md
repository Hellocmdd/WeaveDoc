# 学术工具访谈纪要

## 一、访谈基本信息
- 访谈时间：2026年4月25日 13:00 及随后时段
- 访谈对象：小陈（大二，电子信息专业）、阿睿（博四，生物医学工程）
- 访谈人：访谈员
- 访谈主题：学术写作流、工具协同痛点及 AI 需求调研

## 二、访谈内容

### 1. 写作任务与常用工具
- 本科生（小陈）主要写实验报告和公选课小论文，核心工具是 Word。
- 小陈有时使用飞书协同，但因飞书导出格式混乱，最终需要回到 Word 手动调格式以符合学校模板。
- 博士生（阿睿）主要写 SCI 期刊论文和博士大论文，核心工具链是 Overleaf（LaTeX）+ Zotero + Obsidian。

### 2. 文献阅读与笔记方式
- 小陈较少使用自动管理工具，参考文献主要靠手动编号和录入。
- 阿睿使用 Zotero 标注 PDF，并在 Obsidian 中用自己的话复述结论并摘录数据。
- 阿睿当前痛点包括：笔记与 Zotero 条目链接容易失效、PDF 高亮内容难以反查、公式引用需要手工敲代码。

### 3. LaTeX 与 Word 排版体验
- 小陈认为 Word 排版体验很痛苦，排版约占报告总耗时的 $1/3$ 到 $1/2$。
- 小陈在 Word 中常遇到目录刷新、页眉分节出错，复杂公式下 MathType 容易引发闪退。
- 阿睿对 LaTeX 熟练，但在“拒稿转投”场景（如 IEEE 转 Springer）中，模板转换成本很高，常耗时于导言区兼容性调整。

### 4. 学术 IDE 偏好
- 小陈偏好极简界面，希望“打开就能写”，模板自动套好，不希望有太多复杂按钮。
- 阿睿偏好类 VS Code 的插件化界面，希望分屏显示文件树、文献库、编辑区和 PDF 预览，并保留高度自定义与脚本能力。

### 5. AI 辅助与隐私态度
- 小陈有一定隐私担忧，但更担心被查重系统判定为 AI 代写。
- 阿睿对数据泄露高度敏感，尤其涉及伦理相关实验数据时，认为“本地运行”是使用 AI 的前提。
- 小陈希望 AI 能自动检查字体、编号等格式问题。
- 阿睿希望 AI 做更深层的逻辑一致性检查，而不只是摘要生成。

### 6. 观察受访对象的真实写作全流程
- 第一步：任务分流。本科生任务优先走 Word 快速交付，博士生任务优先走 Overleaf + Zotero + Obsidian 的组合流程。
- 第二步：资料处理。进入写作前先完成文献收集与初筛，但本科生在引用管理上仍高度依赖手工流程。
- 第三步：阅读沉淀。博士生会做“PDF 标注 -> Obsidian 复述记录”的二段式沉淀，但跨工具回链不稳定。
- 第四步：成稿推进。写作阶段在“阅读、笔记、正文编辑”之间频繁切换，形成明显上下文中断。
- 第五步：排版收尾。后期大量时间消耗在模板和格式修复，尤其在公式、参考文献与转投模板场景中最明显。
- 第六步：流程摩擦点。观察到高频存在“出图 -> 截图 -> 中转工具 -> 粘贴 Word”的非规范链路，导致内容一致性和版式稳定性下降。

## 三、整理结论
- 核心痛点集中在跨软件协作断层（公式、文献、笔记）与高强度模板调整成本。
- 关键机会点是打通“阅读-笔记-写作-排版-导出”的连续链路，减少跨工具重复劳动。
- 可优先验证的能力包括：
1. 类 Markdown 写作体验到 Word/LaTeX 模板的稳定映射。
2. PDF 公式到 LaTeX 代码的直接提取与复用。
3. 面向高敏科研场景的本地化 AI 逻辑检查能力。
- 设计上需同时兼容“极简快速写作”与“专业分屏工作台”两类用户模式。
