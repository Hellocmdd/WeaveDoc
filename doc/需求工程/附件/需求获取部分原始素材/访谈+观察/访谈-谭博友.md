# 科研工具使用交流访谈纪要

## 一、访谈基本信息
- 主题：科研工具使用交流
- 记录形式：问答整理
- 受访者：谢承运

## 二、访谈内容

### 1. 写作任务与常用工具
- 平时写作任务主要包括课程论文、英语作业、党建宣传材料。
- 常用工具根据任务类型不同而变化。
- 英语作业以手写为主。
- 党建宣传材料常用 Word、秀米。
- 公式较多的数理或物理类内容偏向使用 LaTeX。
- 纯文字内容多用 Word，图片较多时会用秀米，公式较多时会用 LaTeX 或 Markdown。
- 看文献时会借助翻译软件辅助理解。

### 2. 文献阅读方式
- 阅读文献时通常会下载 PDF 逐页精读。
- 对于不需要精读的文献，会使用 txyz.ai 进行速读，或直接查看摘要。
- 在一些场景下，也会直接把文献交给 AI 获取答案。

### 3. AI 辅助使用情况
- 没有直接让 AI 完整代写内容，但会用 AI 做中英互译、手写公式转 LaTeX、实验报告整理，以及小段内容的润色或改写。
- 提问时总结性问题和具体问题都会用，但总结性问题更多。
- 电脑端主要用于文献总结、从文献中检索关键信息、生成代码。
- 手机端更多用于拍照提问，看纸质教材或作业中的具体问题。

### 4. 工具使用痛点
- 当前最不满意的地方主要有三点。
- AI 写作风格不统一。
- 网络环境切换麻烦，需要频繁切换梯子、武大 VPN，且部分数据库存在 IP 冲突，访问不稳定。
- 不同编辑工具之间格式转换很麻烦，尤其是 Markdown 转 Word 或 LaTeX 时容易乱码。
- Word 很少用于复杂排版，通常只用于纯文字或简单插图；复杂排版更倾向于 LaTeX 或秀米。
- 自己不常手写 Markdown，主要使用 AI 生成的 Markdown，因为内置 LaTeX，转换为 LaTeX 更方便。
- 文件一般统一导出为 PDF，若不在中途切换编辑工具，转换压力不大；真正麻烦的是跨编辑工具迁移。
- 常用工具分别是：LaTeX 用 Overleaf，Markdown 用阅读器，Word 用微软自带工具。

### 5. 文献与 Markdown 工具需求
- 希望工具界面简单，不偏向复杂的 VS Code 风格。
- 期待的功能包括内置 AI 插件，避免把文件上传到外部 AI，可直接对文献提问。
- 希望支持高亮和批注。
- 希望支持多文献、多页面同时打开。
- 希望具备类似 VS Code 的文件管理能力，能够直接打开文件夹内文献，减少重复拖拽。
- 在 AI 部署方式上更倾向云端 API key，不希望使用本地部署。
- 原因是使用轻薄本，也习惯远程服务器运行程序，本地部署维护成本高；同时文献阅读没有特别强的隐私要求。

### 6. 观察受访对象的真实写作全流程
- 第一步：先明确任务类型（英语作业、课程论文、宣传材料、公式类内容），再决定工具入口（手写 / Word / 秀米 / LaTeX）。
- 第二步：进入资料获取与阅读阶段，通常先下载 PDF；根据任务紧急度选择精读、摘要速读或直接向 AI 追问。
- 第三步：把阅读结果转化为可写内容，常见动作是翻译、摘要、提取关键信息、生成代码或整理实验报告。
- 第四步：进入成稿阶段，按目标格式在对应工具中写作（Word 或 Overleaf），Markdown 更多作为中间文本层。
- 第五步：处理中后期格式与迁移，若跨工具转换（Markdown/Word/LaTeX）会出现明显额外成本。
- 第六步：导出与交付，以 PDF 为主；若流程中减少跨工具切换，整体稳定性会显著提升。

## 三、整理结论
- 受访者对“简单、可直接使用、减少格式转换”的工具诉求较强。
- 文献阅读、笔记记录和 AI 辅助之间的衔接，是当前最有价值的工具改进方向。
